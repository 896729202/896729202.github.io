# 线上 Badcase 提炼：从埋点信号到黄金测评集

线上信号只能做初筛，不能直接等同于 Agent 错误。可靠的 Badcase 流程应先扩大召回，再用数据探针归因，最后只把职责范围内、可复现的问题沉淀进黄金测评集。

## Q1. 召回不出来东西的（零召回），全都进入 Badcase 吗？

**绝对不是。** `recall_count == 0` 可能是“真没货”，也可能是“有货但 Agent 没搜出来”。应使用后置分流漏斗，把 Agent 能力问题抓进测评集，把供给问题反馈给招商或搜索团队。

### 1. 用放宽条件的探针区分原因

例如查询为 `{"category": "T恤", "material": "冰丝", "price_max": 200}`，但召回为空，可以做一次逐步放宽的重放：

1. **去掉属性**：暂时删除 `material`，只用品类和价格召回 Top 100 商品，取标题和详情。
2. **文本反查**：用正则或向量检索检查这些文本中是否出现“冰丝”或近义词，如“凉感”“莫代尔”“粘胶纤维”。
3. **按证据分流**：
   - **词表未对齐：进 Agent Badcase。** 商品标题写着“冰丝凉感 T 恤”，结构化属性却填成“粘胶纤维”。Agent 把口语词硬塞进严格的 `material` 字段，没做实体链接或同义词归一化。
   - **约束过严：进 Agent 策略 Badcase。** “50 元以内的纯羊绒大衣”可能确实没有符合条件的商品；但 Agent 只回复“未找到”，没有触发降级策略，也属于交互 Badcase。更好的回复是说明没有完全匹配项，再推荐价格内的仿羊绒或羊毛混纺商品。
   - **供给缺失：剔除。** 女装店铺里询问 RTX 4090，Agent 礼貌拒绝是正常拦截，不应进入 Agent 测评集。

结论是：零召回先做放宽条件和文本反查，再决定是词表、检索策略、交互降级，还是供给问题。

## Q2. 死循环重搜（Re-query / Reformulation）怎么检测？

短时间内反复换词询问同一件事，通常说明 Agent 没听懂，或检索结果一直不符合需求。工程上可以用**滑动时间窗口、语义相似度、槽位差分**联合检测。

### 1. 触发前置条件

同一 `session_id` 下连续至少 3 轮，相邻间隔小于 60 秒，且中间没有点击商品卡、加购或深入询问某个 SKU 等有效转化行为。

### 2. 三个检测算子

- **语义相似但句式改写**：相邻 Query 的句向量余弦相似度较高，例如 `Cosine(E(Q_t), E(Q_{t-1})) > 0.85`，同时编辑距离超过阈值，说明用户在刻意换说法。
- **核心槽位不变，外围槽位反复修改**：连续三轮的 `category` 都是“跑步鞋”，但价格、品牌等条件不断微调，说明用户在迁就 Agent 的检索能力。
- **结果集合高度重叠**：即使用户增加“换一批”“不要黑色”等条件，前后两轮返回的商品 ID 仍高度相同：

  $$\operatorname{Jaccard}(Items_t, Items_{t-1}) = \frac{|Items_t \cap Items_{t-1}|}{|Items_t \cup Items_{t-1}|} > 0.7.$$

  高重叠且用户继续追问，通常指向多轮状态追踪（DST）或去重过滤失效，是优先级较高的 Badcase。

满足前置条件并命中任一算子时报警，再抽取对话、槽位和工具结果复核，避免把正常比较行为误判成死循环。

## Q3. “点进商品卡 3 秒内秒退”能直接算 Badcase 吗？

**不能用固定 3 秒一刀切。** 短点击可能暴露价格、库存或推荐文案错误，也可能只是页面加载慢，或老客快速确认款式后返回。

### 1. 先排除误判

- **可能是真问题**：推荐语写 99 元，详情页显示 299 元；或者点开后发现已售罄、下架。
- **可能不是 Agent 问题**：H5 首屏加载慢、白屏；用户本来就知道商品，只想快速确认图片或款式。

### 2. 用页面生命周期记录真实停留

起点应是商详页首屏核心元素渲染完成（FMP 或 `onPageShow`），而不是点击卡片的时间；终点是页面离开或销毁（`onPageHide`、`visibilitychange` 或返回手势）：

$$T_{\mathrm{dwell}} = T_{\mathrm{leave}} - T_{\mathrm{render}}.$$

### 3. 用组合条件提纯

离线捞取时，至少同时满足以下条件，才把它标为 Agent 秒退 Badcase：

1. **短停留且零交互**：`T_dwell < 3` 秒，或低于该类目停留时长 P10；同时 `scroll_depth == 0`，没有查看尺码或规格。
2. **退回后的负向行为**：返回 Agent 后立即关闭会话，或紧接着质疑“怎么是原价？”“没货啊”等。
3. **群体统计异常**：同一商品被多个不同用户反复点击后秒退，例如连续 10 人出现该行为，再核对 Agent 缓存价格与实时商详页是否脱节。

## 总结：把线上信号变成可用测评集

零召回、连续重搜和 3 秒秒退都只是**初筛信号**。工程上应采用“埋点信号做召回，数据比对和探针做归因提纯”：先识别供给、性能和正常交互，再确认是否属于 Agent 职责范围内的错误。只有经过复核、可复现、能定位原因的问题，才进入 Badcase 库和黄金测评集。
