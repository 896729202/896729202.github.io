原来怎样做 → 现在怎样做，为什么这样改

每排左右是同一阶段，对应框等高对齐。左侧编号是原始 16 轮模型调用，右侧编号是现在的 6 个流程阶段，并不表示每步都调用模型。

先分清：问模型，与让程序执行，是两件事

左侧01–16轮，每轮都调用了1次主模型 API。顺序是：请求模型决定做什么 → 模型返回指令 → 程序执行工具。每项分别列出两段耗时；例如第12轮等模型 6.4 秒，之后工具装配往返 55.9 秒。

平替的是固定决策，不是删掉实际工作。代码直接读规格、写计划或调用装配接口后，这些工具和前后端请求仍存在，只是不必每一步先请求主模型。第10轮的创意模型与生图 API 继续保留；第16轮的自动回复已在 R7、R8 整轮实测通过。

调用数量与旧记录的说明范围

按原始 Langfuse 的 16 条 llm.plan、紧随其后的工具及本地保存回执归纳用途，不是模型内部思考记录。历史快照未保留前两次 read 的文件路径，故只写查阅资料，不指定文档名称。

已记录16次主模型、1次生图服务，另有1次辅助模型；辅助模型用途未在这份历史快照中单独记录，不能硬归到某一轮。这里不是全部 HTTP 请求次数。查看16轮用途与平替说明 →

目前能证明流程提速和保存结果，不能保证画面效果一定更好。

这次保留模型创意及原有制作工具，把固定调度、参数绑定和保存核验交给代码。像素检查、原图追踪、尺寸校验继续保留；但它们不能代替审美、文字准确性和构图检查。旧流程生图后还会再经过模型，新流程目前没有独立的生成后视觉复审。

要确认没有牺牲效果：还需用同一组短需求做新旧多次对照，检查主题符合度、文字与细节、透明背景、切线与关键内容距离，以及实际样片。以下逐项区分“已保留的工作”“已经验证的结果”和“仍待验证的部分”。

现在 ①

把确定的规格与任务准备交给代码

原来为什么慢
模型反复决定“读什么、填什么、下一步做什么”，还要自己填写产品 ID；本次原始记录因此写错一次 ID，并多等了一轮默认值确认。
现在具体怎么做
模型仍理解用户原话，选定品类、主题与制作范围。选定挂件后，代码读取当前产品目录的默认规格，用用户明确指定值覆盖默认值，再走原有参数校验；代码绑定产品 ID、准备设计规则和制作进度。
保留什么，怎样防止做错
保留模型对需求的理解、设计规范和参数合法性校验。自动流程只接管明确选定的标准单片、单面、空白背面新建任务；已有作品、不同背面或特殊白墨等需求不强套这套流程。未识别或缺少必要信息时，仍需正常规划。
验证与取舍
默认值、用户指定尺寸、已有项目保护及特殊范围退出已有回归检查；本轮用普通短句进入流程。减少的是固定内容的反复安排，不代表所有特殊需求都已覆盖。

现在 ②

模型做创意，代码把工艺要求带进生图

这一步解决什么
创意设计本来就需要模型，这一步并未被删减，也不是本轮提速来源。主要改动是前后固定步骤自动接续，避免模型在创作之外反复管理工具与清单。
现在具体怎么做
给模型保留用户主题、文字与参考要求，并加载实体设计规则；模型仍编写人物、构图、风格等创意提示词。原来的制品生图工具再把已选产品的尺寸、透明背景和适用工艺约束编入实际生图请求，生成新原图。
保留什么，怎样防止做错
保留真实模型创作与原图保存。工具读取返回图片的实际字节，检查像素尺寸、比例、透明通道，并在规则明确时检查有效 DPI；明确失败的图片检查会阻止自动装配。代码还核对原图已登记、属于本项目和本产品正面。
验证与缺口
本轮生成了 1 张新透明 PNG 并保存。这些检查不等于画面审美或语义验收：目前没有独立的生成后视觉复审，不能保证人物细节、文字或构图一定不退步；仍缺同主题的新旧画面对照。

现在 ③

原图就绪后自动装配，按回执继续

原来为什么慢
生图完成后，还要等模型更新清单，再等模型发装配指令。图片读取、写入母版和保存是工具实际执行的工作，原本就不是模型在计算像素。
