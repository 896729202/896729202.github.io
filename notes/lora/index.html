01核心知识点与底层原理速记

1. 显存由哪四部分构成？

  • 模型权重（Weights）：前向计算底座。FP16/BF16 下，每个参数吃 2 字节。

  • 梯度（Gradients）：反向传播导数。FP16/BF16 下，每个参数吃 2 字节。

  • 优化器状态（Optimizer States）：AdamW 需要保存 FP32 权重备份、一阶动量、二阶动量，每个参数吃 4+4+4=12 字节。

  • 激活值（Activations）+ 碎屑缓存：每一层前向传播算出的中间特征图，随 Batch Size 和序列长度平方级暴涨；可通过梯度检查点（Gradient Checkpointing）压到极低。

  • 静态显存计算公式（全量微调，16-bit + AdamW）：

    每个参数总开销=2(权重)+2(梯度)+12(优化器)=16 字节
    • 7B 模型静态占用：7×16=112 GB
    • 8B 模型静态占用：8×16=128 GB

2. LoRA 的数学原理与维度推导

  • 前向计算公式：

    输出=W0x+ΔWx=W0x+αr(B⋅A)x

  • 低秩拆解（为什么新增参数极少？）：

    • 原矩阵 W0 维度为 d×k（例如 4096×4096≈1677万 参数）。

    • 矩阵 A（负责降维压缩）：维度为 r×k（8×4096≈3.2万 参数）。

    • 矩阵 B（负责升维还原）：维度为 d×r（4096×8≈3.2万 参数）。

    • LoRA 新增参数量公式：

      ParamsLoRA=(d×r)+(r×k)

      仅占原参数量的不到 0.4%。

  • 初始化设计机制：

    • A 设为高斯分布随机数：保留高维数据降维投影的多样性，打破反向传播的梯度对称性死锁。
    • B 设为全 0：充当阀门，使初始时刻 ΔW=B×A=0，保证 Step 0 模型输出完全等于原预训练底座，不冲击原有能力。

02高频面试真题与标准答题模板

Q1：LoRA 是什么？它的核心原理与初始化机制是怎样的？

参考答案

“LoRA 是一种参数高效微调方法（PEFT）。它的核心假设是模型在特定下游任务上的参数更新矩阵具有很低的本征秩。

具体实现上，它完全冻结原始权重 W0，旁路引入低秩矩阵 A 和 B（维度分别为 r×k 与 d×r），用两者的乘积 B⋅A 来模拟参数增量 ΔW。

初始化时，A 采用高斯随机初始化，B 采用全 0 初始化。这样在初始步（Step 0）时，增量 B×A=0，使模型输出完全与原预训练模型对齐，保证平滑微调。训练第 1 步时，因为 A 非零，B 优先获取非零梯度脱离 0，随后两者协同自激更新。”

Q2：微调时 Rank（r）和 Scaling Factor（α）怎么选？有什么考量？

参考答案

“1. 关于 Rank（r）：

  • 不是盲目越大越好，而是由任务复杂度决定。
  • 格式对齐、分类、简单问答等通用任务，r=8∼16 足够好；复杂推理、代码或大规模领域垂直注入，通常尝试 r=32∼64。
  • 无脑设置过大的 rank 会导致在小样本上严重过拟合，并且削弱低秩约束，引发原模型的灾难性遗忘。
  1. 关于 Scaling Factor（α）：
  • 它在前向计算中以系数 αr 缩放增量 BA。
  • 其核心作用有两点：第一是控制微调知识对原模型的介入强度；第二是解耦 Rank 与学习率（尺度不变性），让不同 rank 尝试时无需重新精细搜索学习率。
  • 工程上通常保持 α=r 或 α=2r（即比例保持为 1 或 2）。”

Q3：为什么说 LoRA 能极大节约显存？参数量不是还有原模型加上 B 和 A 吗？

参考答案

“训练显存开销的最大头不是静态模型文件本身，而是 AdamW 优化器状态（占 12 字节/参数）与梯度（占 2 字节/参数）。

全量微调时，原模型所有参数都要分配梯度和优化器状态（比如 8B 模型仅静态就需要 128GB）。而 LoRA 完全冻结了原模型的全部参数，原权重不计算、不保存任何梯度与动量。LoRA 仅引入了 (d×r+r×k) 的低秩矩阵，可训参数占比通常低于 0.5%，因此原本极其庞大的优化器与梯度显存被砍掉了 99% 以上。”

Q4：手头只有单张 24G 显存的 RTX 4090，要跑 Llama-3-8B（FP16/BF16），全量微调行不行？LoRA 能不能行？

参考答案

“1. 全量微调绝对不行：

  • 8B 模型静态显存为 8×(2权重+2梯度+12优化器)=128 GB。
  • 加上激活值直接突破 140GB，24G 单卡会立即 OOM，至少需要两张 80G A100/H100。
  1. LoRA 微调可以胜任：
  • 原模型冻结仅占 16GB 权重，LoRA 的梯度与优化器只需几百 MB，加上开启重计算后的激活值（约 2～3GB），总显存可稳定在 18～20 GB 左右，正好放进 24G 显存内。”

Q5：微调过程中即使开了 LoRA 依然爆显存（OOM），训练参数里优先调整哪些？

参考答案

“1. 开启梯度检查点（Gradient Checkpointing）：用重算时间换空间，不保留大部分中间层激活值，立即砍掉几 GB 到十几 GB 显存。

  1. 压低单卡 Batch Size + 增大梯度累加步数（Gradient Accumulation Steps）：设 per_device_train_batch_size=1，通过增大累加步数维持整体等效 Batch Size。

  2. 截断最大序列长度（cutoff_len / max_seq_length）：Self-Attention 显存是序列长度的平方阶（O(L2)），截短上下文能立竿见影释放显存。

  3. 升级为 QLoRA（4-bit 量化微调）：用 bitsandbytes 将原模型权重压到 4-bit，8B 基础权重直接从 16GB 缩减到 5GB 左右，整套训练能直接压到 10GB 显存以内。”

Q6：训练好的 LoRA 权重，线上高并发部署时推荐怎么挂载？多业务如何设计？

参考答案

“1. 单任务/固定场景：权重静态合并（Merge-and-Unload）

  • 部署时直接调用 model.merge_and_unload()，将 Wnew=W0+αr(BA) 一次性加回主干权重并保存。
  • 优势：推理时不需要同时走两条旁路计算，零额外推理延迟，零额外显存占用。
  1. 多业务场景（如一套客服、一套润色）：动态挂载架构（如 vLLM / S-LoRA）
  • 显存中只常驻一份通用的 Base Model 骨干。
  • 各业务的小型 LoRA Adapter 权重常驻内存或显存缓存池中，推理引擎在 Batch 处理请求时根据任务路由动态挂载对应的 LoRA 算子，实现一份大底座支持上百种异构业务的高并发请求。”
