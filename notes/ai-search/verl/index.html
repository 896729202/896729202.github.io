verl 实操：PPO、GRPO、DAPO 配置与奖励接入

固定版本，核对算法开关，最后把自定义奖励接入训练。

verl v0.6.0 PPO GRPO DAPO

下载完整 Markdown 原稿

版本说明：以下为 verl v0.6.0 学习示例，不代表当前项目已使用此版本。数值是练习起点，不是唯一正确配置。

  • adv_estimator：优势估计方式。
  • critic.enable：PPO + GAE 通常需要 Critic；GRPO 用组内相对奖励构造优势，通常不需要。
  • rollout.n：每个问题生成几条回答，增加采样通常也增加成本。
  • clip_ratio_low/high：限制新旧策略概率比更新范围，不是裁剪奖励。
  • loss_agg_mode：控制 token 损失汇总，不能仅凭它区分算法。

PPO 还需配置 Critic 模型和优化器；gamma、lambda 控制回报与 GAE。请按锁定版本核对字段和默认值。

GRPO 文档 · PPO 配置 · Critic 配置

2. KL 的两种接入位置

  • 奖励端 KL：algorithm.use_kl_in_reward，把惩罚合并到奖励。
  • 损失端 KL：actor.use_kl_loss，在策略损失中加入 KL 项。

这是可选组合，不是算法强制规定。不要无意中两处都打开而重复惩罚；PPO 也可以关闭 KL。GRPO 示例里的 kl_loss_coef=0.001 只是参考起点。GRPO 示例

3. DAPO 动态采样与超长输出

data.train_batch_size=64
data.gen_batch_size=128
algorithm.filter_groups.enable=True
algorithm.filter_groups.metric=seq_reward
algorithm.filter_groups.max_num_gen_batches=10
reward_model.reward_manager=dapo

按序列奖励过滤训练组。如果同一问题的回答奖励相同，组内可能缺少相对优劣信号，于是继续采样，直到样本够用或达到上限。

视频任务若以 F1 为奖励，可考虑 seq_reward，但需核对奖励返回值和过滤字段；不能不检查就照搬数学任务里的 acc 字段。超长输出字段包括 reward_model.overlong_buffer.enable、len、penalty_factor，是否启用要看输出长度分布。DAPO 配置说明

5. 奖励函数接入

custom_reward_function.path=/实际路径/video_reward.py
custom_reward_function.name=compute_score

实现需解析预测 ID、获取参考 ID、计算 F1；按需调用文本评分服务，并明确奖励归一化、权重、缺失值处理与融合规则。返回结构必须兼容对应版本的 reward manager。

预测 ID 的 4B 模型不能直接当作输出标量分数的奖励模型配置进去就结束。 必须有调用和结果转换逻辑。DAPO 奖励管理器

面试与实操自检

  • 为什么 PPO + GAE 需要 Critic，而 GRPO 通常不需要？
  • 能否区分奖励端 KL 与损失端 KL？
  • rollout.n、clip 区间和 loss 聚合分别影响什么？
  • 为什么不能不检查就把 acc 换成 F1？
  • 能否展示自定义奖励函数怎样解析输出、计算 F1 并返回正确结构？
  • 是否保存版本、配置、日志和独立评测结果？

复习重点：比背住 0.2 或 0.28 更重要的是解释为什么改参数、观察什么日志、如何判断有效，以及独立评测是否改善。本文不代表这些参数已在你的项目中实际运行或验证。
