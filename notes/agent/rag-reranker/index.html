RAG 检索与 Reranker 重排底层原理

用 7 个问题串起双塔检索、交叉重排、注意力矩阵、离线预计算与 Q/K/V 的训练机制。

这 7 个问题沿着同一条线展开：先理解为什么要重排，再看文本怎样进入模型、矩阵怎样交互，最后解释这些矩阵为什么能够学会打分。

本文主要讨论“单向量 Bi-Encoder 检索＋BERT 类双向 Cross-Encoder 重排”。RAG 是检索增强生成的整体流程，不等于向量检索，也不强制使用重排；关键词检索、混合检索、多向量检索和其他重排结构也都存在。

符号统一：用户的问题写作 q，候选文档写作 D；注意力机制中的投影矩阵写作 Qatt,Katt,Vatt。N、M 是问题和文档的 token 数，T 是加入特殊符号后的总长度。Token 不一定等于一个汉字或一个词。

Q1维度的秘密：为什么说 RAG 粗排是“一维”，而 Reranker 精排是“二维”？

对应问题：为什么 RAG 检索后还需要 Reranker？“一维”和“二维”究竟指什么？

先用比喻记住，再把数学说准确

“一维/二维”可以帮助记忆两种交互方式，但不是严格的模型分类。单向量检索把每段文本概括成一条数值数组；交叉重排则允许问题与文档中的 token 在编码过程中直接交互。

一个含 768 个数的向量属于 768 维向量空间，不能因为数组只有一条轴，就说它只有一个特征维度。反过来，双塔编码器内部也有二维注意力矩阵；区别在于问题和文档是否一起参与深层交互。

比较项 单向量 Bi-Encoder 检索 双向 Cross-Encoder 重排

这种独立编码与联合编码的区别，可对照 Sentence Transformers 的双塔与交叉编码器说明。

为什么有了向量相似度，还可能需要重排？

可以把单向量表示想成一张固定格式的摘要卡。它必须在不知道未来问题的情况下，保留对检索有用的信息。比如文档同时写了“支持退款”和“促销商品除外”，而问题偏偏问的是促销商品：主题接近，未必就满足具体条件。

Cross-Encoder 则像把问题和原文一起交给一个评分员。模型有机会在当前问题下检查实体、否定词、数字和条件之间的关系，减少“主题相似但不回答问题”的候选。这提供了更细的建模机会，不保证每次判断都正确，也不保证重排一定提升效果。

“先取前 50 条，再留下前 5 条”是一种配置示例，不是固定标准。重排通常位于召回之后、生成之前；如果相关材料根本没被召回，重排本身也找不回它。流程可对照 Retrieve & Re-Rank 官方示例。

进一步理解：秩瓶颈能说明什么？

假设有 K 个问题和 K 篇文档，分别堆成两个向量矩阵 U,V∈RK×d。如果评分严格采用点积，那么全体配对的分数矩阵是：

S=UVT,rank(S)≤d.

这是直接由矩阵乘法得到的限制：若目标分数矩阵的秩高于 d，固定维度的点积模型就不能把所有目标分数逐项精确还原。归一化后的余弦打分也可以写成这种点积形式。

但这不能直接证明所有排序都做不好，更不能证明“单向量永远无法替代交叉重排”。精确拟合分数与满足排序关系不同；维度、训练数据、任务难度和模型形式都会影响结果。

同样，“向量各向异性”和“长文本信息被稀释”是不同概念。前者描述向量方向分布不均，后者是对摘要丢失细节的直观说法。不能断言文本中 95% 的背景一定决定 95% 的向量方向，也不能断言池化必然丢失所有否定关系。

面试表达： 一维和二维只是记忆交互方式的比喻。真正的差别是“独立压缩后匹配”与“针对文本对联合编码”，重排用更多计算换取更细粒度的相关性判断机会。

Q2矩阵交织的真相：为什么拼接后会出现 N×M 网格，而不是只有 1×(N+M)？

对应问题：Query 和 Document 拼在一起明明是一条序列，二维交互从哪里来？

输入序列和注意力矩阵是两种对象

你的直觉没有错：刚输入模型时，确实是一条序列。忽略特殊符号、令 N=3、M=5，则长度为 T=N+M=8。

阶段 忽略 batch 的形状 每个位置代表什么
Token ID 序列 T 8 个 token 的编号
Embedding / 隐状态 X T×dmodel 每个 token 的特征向量
单个注意力头的 Qatt,Katt T×dk 每个 token 用于匹配的投影
QattKattT T×T 每一行与每一列 token 的配对分数
该头的输出 T×dv 每个 token 聚合后的信息

如果加上 batch 维，一条序列的 ID 通常写成 1×T。这里的“1”是批大小，不能与注意力矩阵的行数混为一谈。

二维表格是在 QKᵀ 这一步出现的

单头缩放点积注意力可以写成：

A=softmaxrow(QattKattTdk+M),O=AVatt.

M 是加性注意力掩码：可见位置取 0，被屏蔽位置取负无穷（实现常用足够大的负数），不是直接把 0/1 二值掩码相加。先忽略掩码，只看乘法形状：

(T×dk)(dk×T)=T×T.

行表示“哪个位置发起读取”，列表示“从哪个位置取信息”。这就是从一条输入序列得到两两交互网格的原因。公式与多头结构见 Transformer 原论文第 3.2 节。

N×M 是完整矩阵中的一个区域

仍然忽略特殊符号，把整个 T×T 矩阵按问题和文档的位置切成四块：

左右滑动查看完整表格 →

行位置 / 列位置 问题的 N 个 token 文档的 M 个 token
问题的 N 个 token N×N：问题内部 N×M：问题读取文档
文档的 M 个 token M×N：文档读取问题 M×M：文档内部

右上和左下两块体现跨文本交互，但其余区域和特殊符号同样会参与计算。不能把完整 Cross-Encoder 的注意力矩阵直接写成只有 N×M，也不能预先认定只有这一块决定分数。

在双向全注意力下，两个方向都可访问；采用因果掩码或其他结构时，可见范围会不同。此外，这个矩阵描述数学运算，优化实现未必会把整张矩阵同时存入显存。

面试表达： 拼接改变序列长度，注意力计算建立位置之间的配对关系。输入是长度为 T 的序列，每个注意力头的完整打分矩阵是 T×T，其中包含 N×M 的问题到文档交互块。

Q3初识双塔：什么是 Bi-Encoder？它和 Cross-Encoder 有什么本质不同？

对应问题：Bi-Encoder 是什么，以及它与 Reranker 的关系。

“双塔”说的是独立编码的两条路径

在本文的单向量检索设定中，文档塔把每个文档块编码为一个向量，问题塔把当前问题编码为一个向量：

u=fθ(q),v=gϕ(D),sbi(q,D)=uTv.

两条路径可以共享权重，也可以使用不同权重；即使共用同一个模型，问题和文档仍是分别编码的，所以仍然属于双塔。“双塔”不要求两台服务器，也不要求一定有两套不同参数。

文档侧可以先完成编码并建索引，问题来了再编码问题。DPR 是使用双编码器做稠密检索的典型研究，可参考 Dense Passage Retrieval 原论文。

Bi-Encoder
  问题 q ── 问题编码器 ── 向量 u ─┐
                                  ├─ 内积 / 余弦 ── 分数
  文档 D ── 文档编码器 ── 向量 v ─┘
          可离线处理并建立索引

Cross-Encoder
  文本对 (q, D) ── 联合编码 ── 打分头 ── 分数

Reranker 是用途，Cross-Encoder 是一种实现

Reranker 指对候选重新排序的组件；Cross-Encoder 是常见实现之一，两者不是完全同义词。用大模型生成判断、用学习排序模型打分，或使用其他交互结构，也可以承担重排任务。

同理，RAG 的召回不一定由 Bi-Encoder 完成。BM25、稀疏检索、混合检索都可能提供候选，之后再交给重排器。

还要区分一个术语：把双塔“最后才见面”口头称为后期交互可以帮助理解，但检索文献中的 Late Interaction 通常特指 ColBERT 这类保留多个 token 向量、再做细粒度匹配的结构。它既能预计算文档表示，又不把文档压成单个向量，不能混成普通单向量点积双塔。见 ColBERT 原论文。

面试表达： 双塔先各自编码，再做廉价匹配；交叉编码器针对问题和文档一起建模。是否共享权重不是区分它们的关键，跨文本交互发生在哪里才是关键。

Q4为什么精排无法“偷懒”？拆解 Cross-Encoder 的现场实时计算原理

对应问题：Cross-Encoder 如何打分，为什么不能预先得到适用于所有问题的最终文档表征？

第一步：把问题和文档作为文本对输入

以 BERT 风格为例，输入可以表示为：

[CLS] 问题 tokens [SEP] 文档 tokens [SEP]

实际使用时通常把两段文本交给 tokenizer 的文本对接口，由它按模型格式添加特殊符号、处理截断和掩码。BERT 风格输入只是示意，其他模型可能采用不同分隔符。

第二步：联合上下文改变隐藏表示

例如文档写着：“苹果富含维生素，苹果手机近期降价。”

  • 问题问“哪种水果含维生素”，相关线索在水果部分。
  • 问题问“数码产品有什么优惠”，相关线索在手机部分。

在联合编码中，同一文档的表示会依赖当前问题。可以把注意力理解为信息路由，但不能据此宣称模型必然给两部分分配 99% 和 1% 的权重；那只是示意，也不是对模型内部过程的实测解释。

第三步：从联合表示中读取用于评分的信息

BERT 类分类模型常使用最后一层的首位置表示，再经过池化或分类头进行预测。它可以被比作“读完问题和文档后的评分员”，但模型并不保证把所有线索完整无误地收集到这里。

不同重排模型的层数、池化方式和评分位置可能不同，不应把 24 层或使用 [CLS] 写成统一规定。可参考 BERT 官方模型与序列分类说明。

第四步：输出当前文本对的分数

示意公式是：

scross(q,D)=wThpair+b.

这里的 hpair 依赖整个文本对。输出可以是原始 logit，也可以经过 sigmoid 等变换；不是所有重排器都必须输出 0 到 1，变成 0 到 1 也不自动等于校准后的相关概率。 例如 BGE 官方说明将 sigmoid 作为分数映射方式，见 BGE Reranker 模型卡。

“不能预计算”的准确范围

关键是一般不能把当前全交互模型对任意未来问题的完整评分，直接等价替换成一个提前算好的、与问题无关的最终文档向量，再做一次点积。

文档清洗、分词、部分查表等工作可以提前做；相同文本对的结果也可以缓存。第一层的某些投影在输入表示已确定时，可能有局部复用空间。但位置、截断和输入模板会影响能复用什么；进入跨文本注意力后的隐藏状态依赖具体问题。

所以不能说“缺少问题，连任何一行计算都无法执行”。准确说法是：要得到这一对问题和文档的联合相关性分数，仍须完成依赖当前问题的交互计算。

面试表达： Cross-Encoder 慢的原因是对每个候选文本对进行联合编码。可以缓存预处理或特定配对结果，但标准全交互结构无法像单向量双塔那样，用一个通用文档向量替代后续交互。

Q5核心本质对比：为什么粗排可以离线提前算，而精排通常需要在线计算？

对应问题：从依赖关系和计算成本上，彻底解释“一个能提前算，一个不能”。

固定资料卡与现场阅读的比喻

把文档编码想成制作资料卡：材料固定时，先把它整理成一个向量；未来的问题来了，只需要把问题也编码，再比较资料卡。

交叉重排更像让评分员带着具体问题阅读原文。资料可以提前收集，但“这份材料是否回答了这一个问题”的联合判断，要等问题确定之后再完成。

资料卡中的坐标是模型学习出来的特征，并不通常对应人能直接命名的“身高”“存款”等固定属性。下面的三维数组只用来演示点积：

u=[1,8,2],vA=[1,9,2],vB=[8,2,1].
uTvA=1+72+4=77,uTvB=8+16+2=26.

这是未归一化的内积分数，不是余弦相似度，也不是概率。它只说明：已有向量时，可以不再为每个文档运行编码器。

真正的区别藏在函数的括号里

计算形式 fθ(q)Tgϕ(D) Fψ(q,D)

“一次编码管一辈子”并不准确。文档、模型权重、tokenizer、切块方式或编码模板变化后，都可能需要重新编码并更新索引。

算一笔时间账，但别把假设写成实测

假设知识库有 100 万个文档块，串行处理一个文本对需要 10 ms，则全库交叉编码的串行估算为：

1,000,000×10 ms=10,000 s≈2.78 h.

若另外假设问题编码 10 ms、索引检索 5 ms、50 个候选的批量重排总计 50 ms，那么两阶段流水线的示意总耗时是 65 ms。这些数字是人为设定的算例，不是性能承诺；批处理 50 对，也没有消除这 50 对的计算。

实际时延取决于模型大小、token 长度、硬件、batch 大小、候选数、精度和并发。不能由单条 10 ms 推出批量一定 50 ms，也不能保证百万向量精确遍历只需 5 ms；大库常使用近似最近邻索引。

因此“先召回、后重排”是常见的成本与效果折中，并非所有规模都必须如此。小规模候选可以直接重排，大规模应用也可能因延迟预算而省略重排。

面试表达： 先看文档表示是否依赖当前问题，再讨论计算量。双塔把大部分文档编码移到离线；交叉编码器把较贵的联合判断留给少量候选，具体收益和时延要实测。

Q6字面拼接还是数学加法？搞懂 Cross-Encoder 的真实输入形态与流向

对应问题：Query＋Document 是原文相加还是向量相加？拼接以后是不是变成了注意力里的 Q？

先澄清“＋”：这里表示组合文本对

它不是把两个句向量逐元素相加，也不要求手写字符串加号。通常把问题与文档分别传给 tokenizer，由模型对应的输入模板组合成一条 token 序列。

下面为了算形状，人为约定“苹果”“手机”等每块恰好是一个 token；真实分词结果以 tokenizer 为准：

问题：苹果 手机             → 2 个 token
文档：支持 七天 退货         → 3 个 token

BERT 风格文本对：
[CLS] 苹果 手机 [SEP] 支持 七天 退货 [SEP]
  1     2    3     4     5    6    7     8

这里有 3 个特殊 token，总长度 T=2+3+3=8。查 token embedding，并按架构加入位置、片段等信息后，得到 X∈R8×dmodel。

输入表示的构造方式可以对照 BERT 的输入定义；其他模型不一定使用同样的片段编码或特殊符号。

用户的 Query 与注意力的 Q 不是同一个对象

用户的 q 是一段输入文本；Qatt 则是一个注意力头里的投影矩阵。由于这里使用自注意力，整条拼接序列都会同时生成三种投影：

Qatt=XWQ,Katt=XWK,Vatt=XWV.
整条序列的隐藏表示 X：包括问题、文档与特殊 token
  ├─ W_Q → Q_att：每个位置用来发起匹配的表示
  ├─ W_K → K_att：每个位置供其他位置匹配的表示
  └─ W_V → V_att：每个位置供加权汇聚的内容表示

所以，注意力的 Q 中不只有问题，K 和 V 中也不只有文档。每一个矩阵都包含这 8 个位置；“查询、键、值”描述它们在运算中的角色。

从配对分数到更新后的词表示

第一步，QattKattT 形成 8×8 的分数矩阵。例如“手机”所在行，可以与“支持”“七天”“退货”等位置对应的键进行匹配。

第二步，经过缩放、掩码和按行 softmax 后，得到每一行的权重分布。点积本身不是概率；归一化发生在 softmax 这一步。不同头、不同层的权重也不必相同。

第三步，把权重乘到 Vatt 上，汇聚信息，再经过输出投影、残差连接和前馈网络等部分，得到下一层隐藏状态。下一层会从新的隐藏状态重新生成 Q、K、V，并不是一直复用最初的三张表。

最后，模型从联合表示中读出相关性分数。首位置打分是 BERT 类模型的常见方式，不是所有重排器唯一的读出方式。

面试表达： 文本对先组合成序列，再形成隐藏状态 X。整条序列同时投影为 Q、K、V；QKᵀ 负责匹配，softmax 后对 V 加权汇聚，最终才读出文本对分数。

Q7随机矩阵的魔法：Q、K、V 的维度结构与训练本质是什么？

对应问题：矩阵明明从随机初始化开始，为什么乘完 W_Q、W_K、W_V 就有对应作用？它们到底是几行几列？

先看单个头：行数来自序列，列数来自投影宽度

继续用第 6 题的 T=8。为便于演示，设 dmodel=4，单头的 dk=dv=4，忽略偏置：

在一般设定下，dk 与 dv 不必等于 dmodel，所以不能把三个投影矩阵一律写成方阵。

若改成 2 个头、每头宽度为 2，那么每个头的 Q/K/V 是 8×2，每个头仍有自己的 8×8 注意力矩阵。两个头的输出拼接为 8×4，再经过输出投影。实现常先做合并线性投影再 reshape；不只是把未经学习的 X 直接切成几份。

加入 batch 后，Q/K 的常见中间布局是 B×H×T×dk，V 是 B×H×T×dv，注意力权重是 B×H×T×T。这里 B 是批大小、H 是头数；具体轴顺序依实现而定。结构与形状可参照 PyTorch MultiheadAttention 文档。

随机初始化没有预设好的“语义标签”

随机初始化并不会自动让某个坐标变成“原因”“结果”或“是否危险”。但从第一天起，运算就已经规定了不同角色：Q 与 K 用来形成配对分数，V 被权重加权汇聚。

因此更准确的说法是：角色由结构指定，能否学到有用的匹配和内容表示，由训练塑造。 对下载的预训练重排模型而言，主体参数通常已经经过预训练及相关性训练，不是在每次推理时重新随机生成，也不应假定所有参数都从零开始只做了相关性分类。

为什么要用不同的投影，而不是直接 XXᵀ？

不同投影允许“一个位置需要的信息”与“另一个位置可供匹配的信息”使用不同表示。忽略偏置时：

QattKattT=XWQWKTXT.

直接用 XXT 是对同一种表示做对称内积；引入不同投影后，匹配关系可以是非对称的，也更容易学习任务需要的关系。

但“一个向量与自己点积永远最大”是错误的。例如 x=[1,0]、y=[2,0]，有 xTx=1，而 xTy=2。只有在等范数或单位归一化等条件下，才有相应的上界结论。

“提问者马甲、标签马甲、内容马甲”可以帮助记忆，却不是每个向量都能被解释成人类语义标签的保证。实际模型学习的是分布式表示。

Q/K 决定权重，V 提供汇聚内容，但信息不只走 V

在注意力支路中，Q 和 K 决定位置之间的权重，V 是被加权求和的对象。可以把前者想成路由，把后者想成被读取的内容。

然而完整 Transformer 还包含残差连接、输出投影和前馈网络。原隐藏状态可以沿残差继续传播；Q/K 对权重的影响也会改变输出。因此，“只有 V 能把信息传到下一层，其他表示绝无信息通路”并不准确。残差与子层结构见 Transformer 原论文第 3.1 节。

反向传播怎样改变这些参数？

用一个简化的二分类训练例子说明，标签 y=1 表示相关，模型输出 logit z，再令 p=σ(z)：

L=−ylog⁡p−(1−y)log⁡(1−p).

如果相关样本的 p 很低，损失会推动参数朝降低这一错误的方向更新。梯度通过打分头、隐藏状态和注意力等计算传回各层。用普通梯度下降作示意：

WQ←WQ−η∂L∂WQ.

W_K、W_V 以及其他参与训练的参数也按各自梯度更新。真实任务还可能使用 pairwise、listwise 等排序损失，优化器也不一定是普通梯度下降。

这不是人工规定“把某个原因词与结果词的分数加 0.001”。每个参数怎么变，由完整计算图、损失和优化器共同决定；一次更新可能影响许多样本。这里的训练过程是教学示意，不声称某个具体模型训练了固定的“几千万道题”。

面试表达： Q/K/V 的计算角色由注意力公式规定，参数通过训练获得有用的投影。行对应 token 位置，列对应每个头的特征宽度；Q/K 负责匹配，V 参与内容汇聚，完整信息流还包括残差和前馈网络。
